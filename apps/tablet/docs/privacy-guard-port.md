# 개인정보 마스킹 재사용 기록

사용자 요청에 따라 ai-security-architecture의 Privacy Output Guard를 정적 브라우저 앱에 이식했다.

- 원본: [policy_core.py / mask_personal_data](https://github.com/ai-agent-orchestrator/ai-security-architecture/blob/00dfd55e4b25161a3d23680c5a896bd7808a1487/python-security-actions/app/security/policy_core.py)
- 원본 브랜치: feat/python-security-actions. 기본 main은 당시 설계 문서 중심이다.
- 이식 버전: legal-pii-2026-11-09-v1-browser-1.
- 위치: src/core/privacy-guard.js, 기존 outbound 경계: src/core/masking.js.

## 그대로 가져온 동작

식별번호(1–8), 전화번호(국제번호·지역번호·070), 이메일 패턴. 탐지용으로만 NFKC 정규화하고 Cf 문자를 제외한다. 교체는 원문의 span에만 적용해 목록 기호·공백·다른 문자열은 보존한다. 결과에는 원래 개인정보 값이나 역매핑 대신 규칙 ID·건수·reasonCode만 반환한다. Python 서버 호출이나 새로운 네트워크 서비스는 추가하지 않았다.

## 브라우저 앱에 맞춘 차이

- API 입력 20,000자와 달리 앱은 최대 500,000자를 받으므로 이메일 패턴의 local/domain 반복을 제한했다.
- 원본 위치 매핑은 JS 정규식의 UTF-16 인덱스에 맞춰 이모지·전각 문자에도 맞게 구현했다.
- 기존 앱의 사용자 지정 단어와 계좌·카드 패턴을 유지했다. 겹치는 탐지 구간은 합쳐 부분 단어 지정 때문에 개인정보 나머지가 노출되지 않게 한다.
- 기존 maskOutbound의 {text,redactions} 계약과 한국어 가리기 태그를 유지했다. 별도 inspectPrivacy가 타입별 집계를 제공한다.
- 이름·기관명·주소는 사용자가 상단 영역에 직접 지정한다. 해당 사전·역매핑은 저장하지 않는다.

## UI와 출력 경계

제목 아래에는 ‘개인정보 보호기능 켜기’ 체크박스, ‘개인정보(주민번호/전화번호/이메일)를 보호해 드려요.’ 설명, ‘추가로 가릴 이름·기관·주소’ 입력만 표시한다. 미리보기·별도 복사·건수·버전·펼침 패널은 제거했다. 기본값은 켜짐이며 토글로 실제 가리기를 켜고 끈다. 원문 입력은 유지하며 켜진 상태의 원문/요약 복사·Drive 제목/본문·판정 보드에 같은 가리기를 적용한다. 클립보드 권한 거부 시에는 복사할 텍스트를 임시 선택 영역에서 제공한다.

선택형 로컬 작업 보관은 원문 근거를 포함하는 기존 기능이므로 체크박스에도 이를 명시했다. 기본값은 꺼짐이며 자동 클라우드 저장은 없다. 규칙 기반 탐지는 완전한 익명화를 보증하지 않는다.

## 검증

원본 테스트의 합성 입력 14개, 070·외국인 식별번호, 겹침·부분 지정, 기존 계좌/날짜 처리, 보드 표시와 내부 근거 비변경을 검사했다. npm run check: 94개 통과 + 프로덕션 빌드 통과. 실제 개인정보를 시험 자료로 사용하지 않았다.

## 배포 갱신

기본 주소를 열 때 이전 캐시가 새 UI를 가리지 않도록 HTML navigation은 network-first, 오프라인은 cache fallback으로 처리한다. 새 서비스 워커는 설치 직후 활성화하고 클라이언트를 맡되 현재 입력 화면을 강제로 새로고침하지 않는다. 캐시 동작은 온라인 최신 HTML·오프라인 이전 HTML·활성화 시험으로 확인했다.
